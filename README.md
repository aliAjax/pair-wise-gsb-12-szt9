# 车辆调度小工具（本地优先）

- 行业：物流
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 规则冒烟测试：`npm run test:smoke`（26 项断言，覆盖裁决、断网合并、迁移恢复）

## 本地优先流程

三张主表（均保存在浏览器 localStorage，单 key 原子写入 `tmp → 正式键`）：

1. **车辆清单** `vehicles`：车牌、默认司机、区域、数据版本 `version`
2. **派车登记** `dispatches`：任务版本、车辆、司机、占用时段、确认时刻 `confirmedAt`、序号 `seq`、同步标记
3. **占用台账** `occupancy`：每条有效任务对应一条 open 占用，完成/取消即关闭释放

### 裁决规则（`src/lib/core.ts`）

- 占用时段采用半开区间 `[start, end)`，首尾相接不算冲突，交叉才算
- 同一车辆重叠时段只能有一个有效任务；同一司机重叠时段不能重复分配
- **同时提交**：`confirmedAt` 小（先确认）的一版保留；相同则按自增 `seq`，再相同按 id
- 败方任务**不入库、不占用**车辆/司机，直接进入**冲突区**；冲突区候选可「放弃」或「采用（自动释放对方占用）」
- 车辆存在未解决冲突时，**车辆卡片标红并暂停该车辆派车**，冲突全部解决后恢复

### 断网与合并（`src/lib/sync.ts`）

- 断网期间派车照常登记：本地立即有效并占用车辆/司机，推送进入**发件箱** `outbox`
- 恢复网络（右上角「切网」）自动合并：先推送发件箱，再拉取远端任务逐条比对
- 远端先确认的任务入库占用，本地败方转冲突区并释放占用；本地先确认则远端版本进冲突区
- 车辆版本号随并发派车递增，版本失配会作为冲突原因之一记录

页面内置演练按钮：**两人同时派车**、**另一调度员派同车**（配合切网演示断网重连合并）。

## 旧数据迁移与中断恢复（`src/lib/storage.ts`）

- 旧记录（`dfwlfront-3-dispatch`）缺少任务版本或占用时段时，**先补齐**（版本 `1`、时段取 `createdAt` 起 4 小时）再参与冲突判断
- 迁移前先写**迁移快照**并加迁移锁，旧记录全程原样保留；迁移成功后解锁
- 若迁移中断（锁残留、本地库未生成），下次启动**从快照重做迁移**，并在页面标注「迁移中断后已从快照恢复」
- 已是新结构但字段缺失的半截数据走幂等 `backfillDb`，可重复执行
- 页面提供「载入旧版数据触发补齐迁移」「迁移中断 → 快照恢复」两个演练入口
